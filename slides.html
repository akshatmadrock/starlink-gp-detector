Where this starts

ECE 257B built a working detector. It has two problems.

What 257B did
  • USRP X310 records Ku-band at 50 MS/s
  • Welch PSD finds the 750 Hz OFDM frame fingerprint
  • z-score threshold at z = 4.0 fires a detection
  • Near-perfect ranking (AUROC ~ 1.0)
The two problems
  • Binary output, no confidence score
  • 70,000 ambiguous windows (z in 2.5 to 4.0) are thrown out entirely
  • For track-before-detect, these borderline windows are the most useful ones
2 / 5
The approach

Swap the threshold for a physics-informed SVGP

  • Additive kernel: each physical evidence source gets its own RBF block
  • ARD per feature: model learns which features matter, lengthscales are interpretable
  • Sparse variational approximation: 300 inducing points, scales to 40k training windows
k(x, x') = k_geom(elevation, angular velocity)  +  k_spec(z-score, harmonics, freq deviation)  +  k_time(hour, day)
each block uses separate learned lengthscales via ARD

Angular velocity (dθ/dt) added as a 9th feature: fast-moving satellites smear the 750 Hz peak, making z-score less reliable even at the same elevation.

Takeaway

Three things I want you to remember

  • Kernel design is the model. A single RBF is 5.7x worse in calibration despite identical ranking. The physics prior is load-bearing.
  • Calibration is not the same as discrimination. AUROC = 1.0 for every model here because the labels are defined by z-score. ECE is the only metric that tells you anything.
  • The "bad" data becomes useful. 70,000 windows the threshold discards now have calibrated probabilities the GP assigns. That is the whole point.
ECE 228 lesson: physics priors belong in the kernel, not just in feature preprocessing.
